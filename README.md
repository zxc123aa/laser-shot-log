# 实验室打靶日志系统

内网部署，A 机（主控）+ B 机（数据机）架构。字段与实验室常规 shotlist 表格一致（时间、No、压缩后、靶类型、靶位、TPS 能量、透射率等 24 列，见 `shotlist_cols.json`，可自行增删改列）。

**B 机扩展——汤姆逊谱仪能量上报**：`thomson_helper.py` 监视汤姆逊图片目录，
图片生成时间 = 发次时间，自动上报发次并在本机小页面（:8767）填入闪烁光纤
能量，按时间窗口自动绑定到 A 机日志对应发次行（`fiber_p_energy` 列）。
详见下文"汤姆逊谱仪能量上报"一节。

## 功能总览

- **多表格管理**：每个实验日/轮次一张表，侧栏切换；新建 / 重命名 / 删除表格
- **记录浏览**：服务端分页（50/100/200/500 每页）、全局搜索（跨所有列）、点击表头排序（升/降序）
- **记录编辑**：所有记录列 + 时间列支持"点击单元格直接输入"（WPS 表格风格），回车保存；时间列有格式校验；配置了 `options` 的列（如"有没有膜"）点击后变下拉选择
- **表格级录入效率**：Tab / Shift+Tab 在单元格间跳转；从 Excel 复制多行多列后直接在单元格 Ctrl+V 批量粘贴（自动按行列分发）；同一行多次写入按行串行执行，不会互相冲突
- **多人协作保护**：每个记录带版本号（乐观锁），两人同时编辑同一单元格时后保存者会收到"已被他人修改"提示并显示最新值，不会静默覆盖
- **列级筛选**：表头下方有筛选行，任意列可输入关键词过滤（可与全局搜索、排序叠加使用）
- **打印**：工具栏"打印"按钮，打印样式只输出表格本体（隐藏侧栏/工具栏）
- **行级操作**：手动新增行、勾选批量删除、单行删除
- **B 机自动上报**：新打靶记录自动写入"实时打靶"表；同秒多发不再被去重规则吞掉（去重键 = 来源+时间+首个文件）
- **目录失效告警**：B 机监视目录被改名/卸载时，本机 ERROR 日志 + A 机页面顶部红色横幅告警（60 秒节流），目录恢复自动通知
- **自动备份**：启动时 + 每 6 小时自动做 SQLite 一致性快照到 `backup/`，保留最近 7 份
- **回收站**：删除行/删表时记录先进回收站，侧栏"回收站"里可单条恢复、彻底删除或清空（原表被删时恢复会自动重建表）
- **状态记忆**：刷新页面后回到原来的表格/页码/搜索词/排序（URL hash）
- **历史导入**：支持导入历史 shotlist .xls（`import_xls.py`），旧库自动迁移到表格结构
- **导出**：当前表 xlsx / CSV；侧栏"导出全部"生成多工作表 xlsx（每张表一个 sheet）
- B 机端保持纯标准库零依赖；A 机导出 xlsx 需 `pip install openpyxl`（CSV 导出不需要）

## 架构

前后端分离：`a_server.py` 只提供 JSON API（表格 sheets / 记录 shots 两级结构，SQLite 存储），
前端是原生 JS 单页应用（首次访问由服务端吐一个 HTML 壳，之后所有数据走 API）。

```
激光打靶一次 ──触发──> 多台谱仪几乎同时落盘文件
                        │
B 机 b_watcher.py 轮询数据目录
  · 发现"新出现的文件"
  · 时间窗分组：相邻 ≤8 秒的文件 = 同一次打靶
  · 取组内最早时间 = 打靶时间
                        │  HTTP POST /api/shot (内网)
                        ▼
A 机 a_server.py :8765（JSON API + SQLite）
  ├── /api/sheets      表格管理（新建/改名/删除/列表）
  ├── /api/rows        记录查询（分页/搜索/排序）
  ├── /api/row         手动新增行 / 批量删除
  ├── /api/field       单元格级保存
  └── /export.xlsx|.csv  按表导出 / 全部导出
                        │
                        ▼
浏览器单页应用 http://A机IP:8765/
  侧栏表格列表 ｜ 工具栏(搜索/分页/增删/导出) ｜ 数据表格(直编)
```

## 部署步骤

### 只有一台电脑？（单机演示 / 单机部署）
- **演示**：双击 `one_pc_test.bat`，A 机 + B 机在本机作为两个进程同时启动，
  按提示按回车模拟打靶，浏览器自动打开 `http://127.0.0.1:8765/` 看日志实时出现；
- **真实单机部署**：不跑演示脚本，同时双击 `start_a_server.bat` 和 `start_b_watcher.bat`，
  并把 `config_b.json` 的 `server_url` 写成 `http://127.0.0.1:8765`、
  `watch_dirs` 写成真实数据目录即可。

### A 机（主控机）
1. 把整个 `auto-experiment-log` 文件夹拷到 A 机；
2. 双击 `start_a_server.bat`（或 `python a_server.py`）；
3. Windows 防火墙放行 8765 端口入站（首次运行弹窗时勾选"允许"即可；
   或手动：`netsh advfirewall firewall add rule name="shots-log" dir=in action=allow protocol=TCP localport=8765`）；
4. 浏览器打开 `http://127.0.0.1:8765/` 确认页面正常。

### B 机（数据机）
1. 拷贝文件夹（至少 `b_watcher.py` + `config_b.json`），确认 B 机装有 Python 3；
2. 编辑 `config_b.json`：
   - `watch_dirs`：改成 B 机上谱仪落盘的真实目录（可多个，递归扫描子目录）；
   - `server_url`：改成 `http://<A机内网IP>:8765`；
   - `machine_name`：B 机标识（多台数据机可共用一个 A 机）；
3. 双击 `start_b_watcher.bat`。首次运行只登记已有文件、不上报，之后每个新文件组 = 一次打靶。

### B 机扩展：汤姆逊谱仪能量上报（thomson_helper.py）

汤姆逊谱仪单独一个目录，出图时间即发次时间；解谱出的闪烁光纤能量要绑定到
正确的发次。`thomson_helper.py` 负责整条链路：

```
汤姆逊出图（一次一发）──> helper 监视目录，时间窗分组 = 发次（生成时间=发次时间）
        │ 自动 POST /api/shot 上报发次（auto_report 可关）
        ▼
解谱完成后，浏览器打开 http://127.0.0.1:8767（B 机本机页面）
  · 按发次列出待填能量，填入"闪烁光纤能量"点"发送"
  · A 机 /api/energy 按时间窗口（默认 ±15s，可配）找最近发次行，
    能量写入 fiber_p_energy（闪烁光纤质子能量）列
  · 页面显示绑定结果："→ 行时间（差 N 秒）"
```

**绑定兜底**（重点）：
- 窗口内找不到发次（如 A 机当时宕机漏记）→ 状态"无匹配发次"，
  页面显示 A 机最近一条记录时间，点"补录"强制建一条独立记录；
- 能量可以重发覆盖（解谱修正后点"重发"即可）；
- 发次与能量状态持久化在 `state_helper.json`，B 机重启不丢；
- 断网时发次上报进补发队列，恢复后自动重发。

配置 `config_helper.json`（首次运行自动生成）：

| 字段 | 默认 | 说明 |
|---|---|---|
| `watch_dirs` | `["D:\实验数据\汤姆逊谱仪"]` | 谱仪图片目录（**列表**，可多个；兼容旧的单目录 `thomson_dir` 写法） |
| `server_url` | — | A 机地址 `http://<IP>:8765` |
| `machine_name` | 主机名-Thomson | 上报标识（C/D 机部署时改成各自标识即可） |
| `group_window_sec` | 8 | 多少秒内的图算同一发 |
| `match_window_sec` | 15 | 能量绑定时间窗口（±秒） |
| `helper_port` | 8767 | 本机填能量页面端口（各机可相同，均为本机访问） |
| `energy_field` | `fiber_p_energy` | 能量写入的列（key） |
| `auto_report` | true | 是否自动上报发次；若 b_watcher 也监视同一目录请关掉一个，避免重复 |

双击 `start_thomson_helper.bat` 运行。

> **C/D 机扩展**：这套 helper 是通用的"谱仪上报终端"——拷贝文件夹 → 改
> `config_helper.json`（目录、机器名、端口）→ 开机自启，即完成一台新谱仪
> 机器的接入。界面与主系统同一套风格，B/C/D 各机互不影响。

### 开机自启（可选）
- 简单方式：把对应的 `.bat` 快捷方式放入 `shell:startup` 文件夹；
- 服务方式：用 Windows 任务计划程序 → 创建基本任务 → "计算机启动时"运行 bat。

## 文件说明

| 文件 | 位置 | 作用 |
|---|---|---|
| `a_server.py` | A 机 | 日志服务器：JSON API + 单页前端 + SQLite 存档 + 导出 |
| `b_watcher.py` | B 机 | 数据目录监视器：新文件 → 时间窗分组 → 上报 |
| `thomson_helper.py` | B 机（汤姆逊） | 发次检测 + 闪烁光纤能量绑定上报（本机页面 ：8767） |
| `config_b.json` | B 机 | 监视目录 / A 机地址 / 机器名 / 轮询与分组参数 |
| `config_helper.json` | B 机（汤姆逊，自动生成） | 汤姆逊目录 / 绑定窗口 / 页面端口 / 能量列 |
| `config_a.json` | A 机 | 访问白名单（allow_ips，空 = 不限制） |
| `shotlist_cols.json` | A 机 | 记录列配置（24 列，可增删改列，刷新生效） |
| `import_xls.py` | A 机 | 历史 shotlist .xls 导入工具（需 xlrd） |
| `shots.db` | A 机（自动生成） | SQLite 存档：sheets 表格 + shots 记录 |
| `backup/` | A 机（自动生成） | 自动备份目录（每 6 小时，保留 7 份） |
| `state_b.json` | B 机（自动生成） | 已见文件清单，重启不重复上报 |
| `unsent_b.json` | B 机（自动生成） | 断网时暂存的未上报记录，恢复后自动补发 |

## 参数建议

- `group_window_sec`（默认 8 秒）：一次打靶多台谱仪落盘的最大时间差。若某台谱仪写盘慢
  （大文件刷写 >8 秒），适当调大；若打靶频率极高（连续 >1 发/10 秒），适当调小。
- `scan_interval_sec`（默认 3 秒）：轮询间隔，越小发现越及时，负载略增。
- 判定规则只看"新文件出现"，不依赖文件名格式；任何谱仪目录都适用。

## 注意事项

1. **时间同步**：打靶时间取的是 B 机文件 mtime，A、B 两机最好都开启 Windows 时间同步
   （设置 → 时间和语言 → 同步；或统一指向内网 NTP），否则时间轴会有偏差。
2. **文件还在写入就上报？** 不会——最后一组文件会等它"安静"超过 `group_window_sec`
   才上报，写大文件的谱仪不受影响。
3. **B 机不允许装 Python？** 把 B 机数据目录共享出来，在 A 机上直接运行 `b_watcher.py`，
   把 `watch_dirs` 写成 UNC 路径（如 `\\B-PC\共享名`）、`server_url` 写 `http://127.0.0.1:8765`
   即可，同一套代码两用。
4. **丢数据？** B 机断网期间记录暂存在 `unsent_b.json`，网络恢复自动补发；A 机日志都在
   `shots.db`，可用任何 SQLite 工具查看。
5. **想再加字段**（打靶序号、操作人等）：改 `shotlist_cols.json` 即可（网页/导出同步生效，无需动代码）；
   想给某列加下拉选项：给该列加 `"options": ["选项1", "选项2"]`。
6. **导入历史表格**：`python import_xls.py <xls路径> [日期] [--sheet 表名]`，默认按日期归入同名表格，重复导入自动跳过。
